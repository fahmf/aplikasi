1 Ringkasan Sistem

Sistem terdiri dari 3 komponen: Mobile App (murid), Admin Web Panel (ustadz/pengajar), dan API Backend (single source of truth).

👤 Aktor

Murid (Student)

Login, pilih pelajaran, kerjakan wahdah, lihat progress & leaderboard, kumpulkan XP dan badge.

👨‍🏫 Aktor

Ustadz (Admin)

Kelola pelajaran, wahdah, soal; pantau progress murid per kelas; review jawaban salah.

🔧 Aktor

Super Admin

Kelola ustadz, kelas/fashl, konfigurasi gamifikasi (XP rules, badge tiers).

Alur data inti

Admin buat konten

Ustadz via admin panel: buat Pelajaran → tambah Wahdah → input Soal (pilihan ganda, susun kata, cocokkan).

Murid daftar & pilih pelajaran

Student register, pilih pelajaran yang tersedia (Qiraah/Imla'/Balaghah) dan otomatis enroll ke Wahdah 1.

Kerjakan Wahdah

Sistem serve 10 soal dari bank soal Wahdah tsb; tiap jawaban dicatat ke attempts; nyawa (hearts) berkurang jika salah.

Selesai → hitung skor & XP

Skor ≥70% = lulus → buka Wahdah berikutnya + tambah XP + cek badge baru + update leaderboard.

Checkpoint tiap 4 Wahdah

Tes menyeluruh 20 soal (campuran dari 4 Wahdah terakhir); harus lulus 70% untuk lanjut.

3 Skema Database (PostgreSQL)

Berikut DDL singkat untuk tabel inti. Gunakan uuid untuk primary key dan jsonb untuk data fleksibel (response soal campuran, badge rules).

-- Pelajaran: Qiraah / Imla' / Balaghah
CREATE TABLE lessons (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  code text UNIQUE NOT NULL,              -- 'qiraah' | 'imla' | 'balaghah'
  name_ar text NOT NULL,                 -- 'القراءة'
  description_ar text,
  level text,                            -- 'mubtadi' | 'mutawassit' | 'mutaqaddim'
  icon text, color text,                -- untuk styling UI
  sort_order int DEFAULT 0,
  created_at timestamptz DEFAULT now()
);

-- Wahdah (unit) dalam pelajaran
CREATE TABLE units (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  lesson_id uuid REFERENCES lessons(id) ON DELETE CASCADE,
  number int NOT NULL,                    -- 1..8
  title_ar text NOT NULL,
  description_ar text,
  is_checkpoint boolean DEFAULT false,    -- true untuk wahdah 4 & 8
  passing_score int DEFAULT 70,           -- % minimum
  xp_reward int DEFAULT 120,
  UNIQUE(lesson_id, number)
);

-- Soal; prompt_ar bisa rich (HTML ringan) untuk kata yang diberi warna
CREATE TABLE questions (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  unit_id uuid REFERENCES units(id) ON DELETE CASCADE,
  type text NOT NULL,                    -- 'mcq' | 'mcq_harakat' | 'arrange' | 'match'
  prompt_ar text NOT NULL,
  explanation_ar text,                   -- ditampilkan setelah jawab
  media_url text,                         -- audio untuk qiraah / image
  xp_reward int DEFAULT 10,
  sort_order int,
  metadata jsonb DEFAULT '{}'          -- hints, tags, difficulty
);

-- Opsi jawaban (berlaku untuk mcq, arrange, match)
CREATE TABLE choices (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  question_id uuid REFERENCES questions(id) ON DELETE CASCADE,
  text_ar text NOT NULL,
  is_correct boolean DEFAULT false,       -- untuk mcq
  sort_order int,                           -- urutan jawaban benar untuk 'arrange'
  pair_key text                            -- untuk 'match' (pasangan A↔B)
);

-- Percobaan pengerjaan wahdah
CREATE TABLE attempts (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid REFERENCES users(id),
  unit_id uuid REFERENCES units(id),
  score int,                                -- 0-100
  stars int CHECK (stars BETWEEN 0 AND 3),
  xp_earned int,
  passed boolean,
  hearts_used int,
  started_at timestamptz DEFAULT now(),
  finished_at timestamptz
);

-- Progress pengguna per pelajaran (denormalized untuk dashboard cepat)
CREATE TABLE user_progress (
  user_id uuid REFERENCES users(id),
  lesson_id uuid REFERENCES lessons(id),
  current_unit int DEFAULT 1,
  total_xp int DEFAULT 0,
  level int DEFAULT 1,
  streak_days int DEFAULT 0,
  hearts int DEFAULT 3,
  last_played_at timestamptz,
  PRIMARY KEY (user_id, lesson_id)
);
Catatan: response di tabel answers disimpan sebagai jsonb agar bisa menampung format berbeda — MCQ: {"choice_id": "..."}, Arrange: {"order": ["id1","id2","id3"]}, Match: {"pairs": [["A1","B3"],["A2","B1"]]}.

4 API Endpoints (ringkasan)

Auth & User

POST/api/auth/registerDaftar murid baru
POST/api/auth/loginLogin, kembalikan JWT
GET/api/meProfile + XP + level + streak

Pelajaran & Konten (murid)

GET/api/lessonsList pelajaran + progress user
GET/api/lessons/:id/unitsList wahdah untuk dashboard (path)
GET/api/units/:id/questionsAmbil 10 soal untuk sesi (tanpa bocorkan is_correct)
POST/api/attemptsMulai percobaan baru → kembalikan attempt_id
POST/api/attempts/:id/answerKirim jawaban per soal; server cek & kembalikan feedback
POST/api/attempts/:id/finishSelesai; hitung skor, XP, unlock wahdah next

Leaderboard & Sosial

GET/api/leaderboard?scope=class|friends&period=week|month|allRanking
GET/api/badgesBadge yang dimiliki + locked

Admin (butuh role=admin)

GET/api/admin/lessonsCRUD pelajaran
POST/api/admin/unitsTambah wahdah
POST/api/admin/questionsTambah soal (beserta choices)
PUT/api/admin/questions/:idEdit soal
DELETE/api/admin/questions/:idHapus soal
POST/api/admin/importBulk import dari CSV/Excel
GET/api/admin/classes/:id/progressLaporan progress per kelas

6 Alur Input Soal (admin side)

Pilih pelajaran target

Sidebar: Qiraah / Imla' / Balaghah. Jika belum ada, Super Admin buat dulu di menu Pelajaran.

Pilih atau buat Wahdah

Minimal 8 wahdah per pelajaran, wahdah ke-4 & ke-8 otomatis ditandai sebagai checkpoint.

Tambah soal (10 per wahdah)

Pilih tipe → isi prompt Arab → tambah opsi → tandai jawaban benar → tulis penjelasan → save sebagai Draft.

Preview & uji coba

Tombol "Preview sebagai Murid" — render tampilan mobile persis; admin bisa test jalur soal sendiri.

Publish

Setelah ≥10 soal lengkap, tombol Publish aktif. Saat publish, wahdah langsung visible untuk murid yang sudah lulus wahdah sebelumnya.

7 Logika Gamifikasi

ElemenFormula / Aturan
XP per soal10 XP (benar pertama kali) · 5 XP (benar setelah salah) · 0 XP (salah)
XP bonus wahdah lulus+50 XP dasar, +30 XP jika tanpa salah, +20 XP jika < waktu target
XP checkpoint+200 XP (lulus), multiplier 2× jika bintang 3
Levellevel = floor(sqrt(total_xp / 100)) + 1 — butuh lebih banyak XP tiap level
Bintang wahdah3★ = 100% · 2★ = 80-99% · 1★ = passing_score-79% · 0★ = gagal
Hearts (nyawa)Mulai 3, berkurang 1 tiap salah. Habis = gagal, regen 1/30 menit atau nonton iklan
Streak+1 tiap hari ada aktivitas belajar; reset jika >24 jam tidak aktif
BadgeDidefinisikan oleh rule jsonb, contoh: {"type":"streak","value":7} → badge "سلسلة ٧ أيام"

8 Rekomendasi Stack

🚀 Cepat & Indonesia-friendly

Laravel + MySQL + Inertia

Paling populer di komunitas dev Indonesia. Laravel handle auth, validasi, admin panel (Filament) nyaris tanpa kode. Deploy ke VPS murah.

⚡ No-code friendly

Supabase + Next.js

Database + Auth + Storage + Realtime leaderboard langsung jadi. Admin panel cukup pakai Supabase Studio, atau build sendiri dengan Retool/Refine.

🎯 Type-safe full-stack

Node.js + PostgreSQL + Prisma + tRPC

Untuk tim dev berpengalaman JS/TS. Schema dibagi antara web & mobile, type aman end-to-end.

📱 Mobile

React Native (Expo) atau Flutter

Dua-duanya bisa handle RTL + font Arab dengan baik. Expo lebih cepat iterate; Flutter lebih smooth untuk animasi gamifikasi.

Rekomendasi: Untuk pesantren / lembaga kecil-menengah, mulai dengan Supabase + Next.js (admin) + React Native Expo (mobile) — bisa running dalam 2-3 minggu dengan 1 developer, biaya hosting gratis sampai beberapa ribu pengguna aktif. Scale up ke Laravel/PostgreSQL penuh kalau sudah > 10k user.
